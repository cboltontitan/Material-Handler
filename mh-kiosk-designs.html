Material Handler kiosk · design review

Material Handling Board

Two layouts for the shared-queue kiosk, both in the pick_worker look (Hub Transfers v2.1): fat name buttons, card rows, one green action. The queue is grouped by the assigned assembler and ordered by each assembler's schedule priority, so an MH can pull everything for one assembler in the order they'll build it. Tap an option's cards — the drill-in works.

Screen 1 — Tap your name both options

Straight from pick_worker / kiosk_home: one fat button per active MH operator from the shared roster (department = Material Handling). Adding or retiring someone is a roster change, never a form edit.

Option A — One list, assembler section breaks

Everything on one scrolling screen. A blue section rule starts each assembler's batch; cards carry the actions inline. Fewest taps; best when the queue is short (it holds exactly one WO today).

Option B — Assembler batches, then drill in tap a card

Faithful to pick_worker's pick-list flow: the queue screen shows one card per assembler (a "pull batch"), and opening it shows only that assembler's jobs. Cleaner when the queue grows; one extra tap per batch.

  • Batch card = MyPickRow: name, job count, piece count, next due, problem badge; urgency stripe on the left edge.
  • The first job's PARTIAL / PROBLEM panel is opened here to show the flow: adjust the quantity, or tap a reason (or both — "moved 6, then ran short").
  • Qty > 0 → sp_pc_complete_step as a partial; reason picked → Problem event + PC notification. Confirm dialog before anything writes.
  • COMPLETE ALL asks "Complete YS82BC0200 — all 16?" then writes; the Ready cascade flips Assemble and the WO lands on the supervisor board by itself.

Both options share every screen and mechanic except the queue layout — so this is one decision: A (one list) or B (batch drill-in). Mixes are easy too (e.g. B's batch cards with A's inline problem badge).
